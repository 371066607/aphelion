## 1. 目标与范围

让正常 `game.html` 中的殖民地看起来像一处正在被幸存者修建的异星家园：人物、自然环境、家具、光照和界面使用同一套视觉规则，玩家能看懂空间并完成建造。

首个交付是**正式游戏中的迫降点＋一间卧室＋一间工作间＋周边植被的完整视觉样板**，验证后再扩展到全地图。样板通过正式建造与居民行为形成；自动化测试可另用明确标注的夹具。普通新档仍三人起步，不赠送建成房屋、不改变初始资源。

采用已有方向：奶油白回收舱板、青绿旧设备、土色地面、织物床褥和暖橙灯光；正交俯视、轻手绘、柔和接触阴影。沿用现有人物与家具，优先补齐出现频率最高的环境素材。参考 `docs/prototypes/building-v4-art-direction.md:23` 和 `docs/colony-home-plan.md:5`。

本轮不新增玩法系统、建筑经济、科技、地图生成规则或存档字段；不更换引擎、不改为 3D、不做全目录重画、不重做人形动画。不把原型或概念图当作正式游戏的验收结果。

## 4. 必须守住的视觉与数据规则

1. **地图只有一个事实源。** 纹理和地形边缘从当前 Observation/TerrainModel 读取；不得随机画出逻辑上不存在的湖岸、资源或可走区域。地形变化仍走现有 revision 与 LRU 缓存（`src/world.js:50-93`）。
2. **绘图尺寸与逻辑占格分开。** 家具、墙门依旧由 BuildGrid 决定放置、点击、通行和互动格（`src/entities.js:451-477`）。不能通过缩碰撞盒、平移旧坐标让截图看起来好看。
3. **建筑保持全不透明。** 沿用日夜整张 tint 切换；禁止原图与夜图透明混合。树冠遮挡首选轮廓/前景提示而非整株淡出，避免把建筑透明度红线扩散成新的例外。
4. **树冠可以大于资源交互基底。** 固定脚点与 Y 排序，分别定义绘图包围盒、基底和命中范围；适配视口剔除边距，避免大树在屏幕边缘突然消失。不得让树冠扩大自动改变采集距离或寻路。
5. **UI 只读现有业务状态。** 总物资、可用物资、在途/预订物资需要明确口径，不能为显示漂亮重复计数或把旧数字库存当成全部库存。复用 `APH.Colony` / `APH.Storage` 查询。
6. **装饰不冒充玩法。** 舱板碎片、地面擦痕是表现层细节；可点击的箱子或可采集残骸必须对应已有实体/库存。若要增加实体、碰撞、资源或改变开局布局，另列契约变更，不混进本视觉任务。
7. **光照不改变模拟规则。** 电源开关等既有状态驱动灯光；调整可见度不改昼夜长度、敌方视距、取暖效果或生产数值。

- 固定 seed 58098、视口 1440×900、缩放和昼夜时刻，记录当前新档、墙角门洞、四向家具、菜单、人物选择的截图与 DOM/状态证据。
- 同时保留普通新档与独立样板档；两者使用隔离浏览器存储，不清理用户现有存档。
- 从现有 `tests/home_live_probe.js`、`tests/colony_perf_live_probe.js`、`tests/camera_live_probe.js`、`tests/dual_world_live_probe.js` 复用采样方式；不能拿自由建造截图替代采集施工的行为验收。

**验收：**能在同一条件下复现画面；现有性能失败单独登记；不宣称本计划已经获得新的构建/测试证据。

### P1：制定一页视觉规格并准备最小资源包

- 以现有人物为比例基准，不先改人形高度。列出人物、床、门、树干、树冠、灌木和箱子的同屏尺度图；树冠高度先以人物约 1.5～2 倍作样板试值，最终以遮挡和操作可读性决定。
- 色彩语义统一：土/草为低饱和背景，奶油白为建筑，青绿为设备，暖橙为生活光源；红色只突出危险，选择与规划用独立高对比描边。UI 尽量使用同一组颜色变量。
- 最小资源包：树 2 个变体、灌木 2 个变体、石块与铁矿各 1 组、基础土/草纹理与边缘、迫降补给视觉组件。变体由实体 id/seed 稳定选择，读档不换外观。
- 复用 `assets/building/warm-settlement-atlas.png` 的家具与材质。新增环境素材使用独立图集，不挤占现有实测裁切矩形。
- 生成新栅格素材时使用 imagegen 技能/工具；先核对现有图片，再按统一规格生成。保留原稿，透明背景必须真实透明；裁切、脚底、接触阴影和图集边缘人工检查。
- 数据入口优先沿用 `assets/build_sprites.py` / `src/sprites.js`；若静态环境需独立嵌入生成器，按现有 building_art 模式接入 `build.py`，不引入打包器或运行时外链依赖。

**验收：**同屏尺度图能区分人、树、资源和家具；无白边/假透明；素材缺失时仍有可辨认的程序绘制回退。此时只认可资源与比例方向，不宣布正式场景完成。

### P2：在正式游戏里完成环境、迫降点、房间和夜景样板

**P2.1 地面与植被**

- 主要改 `src/world.js:paintChunk` 与 `src/entities.js:drawFlora`；素材映射及可调数值放 CFG/资产数据表。
- observed 地面在分块缓存生成时加入低频纹理与邻接过渡；跨 chunk 边界取一致世界坐标采样，避免接缝和滚屏闪烁。
- 水域、岩地与可建区域边界必须可辨；“柔和”只影响材质，不模糊真正的通行边界。保留图层/检查器读取精确格语义。
- 植物保持 uid、kind、脚点、耐久、采集抖动与耗尽恢复链。选中人物被树冠挡住时以清晰轮廓标记位置，不持续叠一层需求文字。

**P2.2 迫降点**

- 审核已有 HAB、`landing_cargo` 和 `bl_landing_pad` 的空间关系，分别表达“迫降补给”与“出发位置”。发射台不能仅因外观替换而被改成另一个玩法对象。
- 用已有补给位置的外观、地表擦痕和不影响行走的舱板细节形成视觉中心；临时照明对应现有常亮家园光源，不新增可利用能源。
- 不额外撒布可采集资源、不压住合法建地、不移动现有物资。若舱体造型必须新增大块阻挡，先拆成独立设计问题，本轮用较小组件完成中心。

**P2.3 房间与墙门**

- 改 `src/entities.js:drawWalls/drawGeometryFurniture`，必要时调整 `src/building_art.js` 材质映射。保留 48px 连续格，利用墙顶明面、内侧窄阴影和门框轮廓建立厚度。
- L/T/十字连接只描外边界，不逐格画内框；门开闭状态可读，绘图不能伪装出逻辑不存在的门洞。
- 实际建造一间三床卧室和一间工作间，检查三人进出、到床休息、到场工作。通过现有资源与解锁过程搭建；测试夹具单独标注、不得写入默认新档。

**P2.4 夜景**

- 修改 `src/world.js:drawDarkness` 的家园分支和相关 CFG 数值：提高最低环境可读性、减弱黑绿偏色与过强暗角，让房间、路径、水岸在灯外仍可识别。
- 家园移除依赖旧玩家 `s.px/s.py/face` 的手电筒式光圈，保留有明确世界来源的迫降点、路灯、已有篝火等光照；远征原光照本轮保留并回归检查。
- 先统一光源位置、开关和颜色，再检查图集夜色；建筑维持不透明绘制。避免每帧重建纹理或对每个像素做实时计算。

**验收：**同一正式场景白天/黄昏/夜间都能辨认房间、门、人物、资源和路线；缩放、滚屏、断电后光源语义正确；新旧档读取不丢物资、不移动建筑；没有改变地图、生产和采集结果。

### P3：统一建造菜单、HUD 与人物条

- `src/ui.js:renderBuildRow` 与 `template.html`：目录分“结构、生活、生产、仓储、电力、防御”，默认结构类让墙、门、地板容易找到；未解锁项可查看但弱化，显示清楚的解锁原因，不伪装成缺料。
- 目录使用真实资产缩略图＋名称；选中后显示完整材料、占地、朝向与建造时间。材质颜色不再按数组顺序循环分配。缺少图标时给有文字的统一回退。
- 中文材料名从已有资源别名/定义统一映射，补齐 wood/iron/stone；已具备基础建造权限的项目不应同时显示“尚需研究”的矛盾提示。
- 保留“缺料也可规划”、四向旋转、取消、连续墙、拉框地板、Enter/Space 与键盘导航；在详情中区分库存不足与禁止建造。
- `updHUD`：家园显示人口/床位、食物、建材、时间天气、电力与危机；远征负重、异常等随场景切换。高级材料可折叠，默认界面不铺满零值。
- `colonistBarHtml/renderColonistBar`：头像复用 `src/humanoid.js:appearance/poseFor` 等实际外观来源，离屏缓存静态头像；依 id/外观变化失效，不每帧裁切整张表。保留征召、倒地、选中和镜头聚焦语义，避免表情覆盖人物身份。
- 人物条、检查器、底栏和建造抽屉统一字体、边框、底色、间距；正文建议起始 13～14px，次要文字不低于 12px，最终按桌面视口检查溢出和可读性。
- `armProbe`、`brFreeBuild` 和免费建造快捷入口仅在显式调试模式开放；优先复用现有 `debugkeys=1` / `freebuild=1`，统一定义显示与启用条件。普通 `autostart=1` 不等于调试开关；测试需要探针时显式请求，保留标题/DOM可观察性。

**验收：**不用横向翻找即可进入结构类；菜单、预览、落地物能认出同一对象；三名殖民者头像能对应场上人；家园无远征零值和调试控件；鼠标与键盘均可完成选择—放置—旋转—取消。

### P4：扩展到完整地图与常用状态

- 样板成立后补齐剩余资源/异星植物的同风格映射，防止只把出生点画好；保留群系、矿物、植物的辨识差异。
- 巡查地图边缘、湖岸、树林、矿区、旧档建筑、蓝图与拆除状态。新增墙材质兼容旧坐标，不重新吸格。

- 只同步原型与正式模块共享的资源；原型依然作为隔离回归入口，不扩成第二套完整游戏。

**验收：**多区域与常用状态无明显旧占位风格遗漏；纹理缓存有上限，大对象无边缘闪现；同 seed 跨读档资源状态和变体稳定。

| 资源 | 原图、透明图集、裁切、离线加载失败 | 无假透明/邻帧污染；回退可运行；新增尺寸与锚点有记录 |
| 地形 | 多 seed、跨块/滚屏、observed 与旧档 | 水与路与真实格一致；不改变资源清单、寻路、肥力；无缓存错用 |
| 建造 | 四向家具、L/T/十字墙、门洞、预览/点击/施工 | 同一 BuildGrid 占格；三人真实通行；无透光缝或重复描边 |
| 光照 | 昼/昏/夜、平移缩放、通电/断电 | 环境与人物可读；光源位置有依据；建筑不透明，远征无回归 |
| UI | 开局菜单、锁定/缺料、人物选择、场景切换、键盘 | 中文一致、状态真实、常用项好找；无溢出、焦点丢失与误触 |
| 存档 | 老档、普通新档、建设中保存恢复 | 物资/队员/位置/蓝图保持，渲染资产不改变业务数据 |
| 性能 | 同 seed、20居民、约2000对象，日夜与缩放 | 报告 frame CPU p95、模拟/寻路、缓存量、文件体积和启动解码；可复现，绝不以 DOM 桩代替真实 Canvas |

按改动复用 `tests/building_art.test.js`、`tests/wall_visual.test.js`、`tests/map_single_source.test.js`、`tests/terrain_model.test.js`、`tests/building_proto_ui.test.js`、`tests/home_contracts.test.js`、`tests/scenario.test.js` 的相关覆盖。不要将独立 scenario/perf/boss 入口塞入纯注册单测扫描流程。

真实浏览器复跑现有 home/camera/dual_world/colony_perf 探针，输出到新的 evidence 目录。实施时若工具规则要求使用 CUA 浏览器控制，则通过其允许接口复现探针步骤，不另起未经允许的浏览器自动化通道。桌面画面验收必须包含普通入口，不能只带 autostart 和自由建造参数。

**已知基线问题：**本次会话此前检查结果为构建通过、1077 单元/161 场景/7 Boss 通过；性能 5 通过/1 失败，80 人型敌对的 5 次生产结算为 515ms、复跑 526ms，超过 500ms 护栏。1077 包含工作区已有的未提交测试；这是历史基线，不能算未来视觉实现的通过证据。实施前先复现，任务完成时性能门禁仍红就明确未达完成标准，不能调高阈值掩盖，也不擅自占用 #208 的改动。

建议视觉增量预算：同机同条件浏览器前后各测至少三组，目标 frame CPU p95 不超过 16.7ms 且相对基线增幅不超过 10%；超限先定位。该目标是实施预算，不是当前性能结论，也不构成对所有机器 60fps 的承诺。记录图集/HTML 增量与冷启动时间；优先静态图集、按需解码、地形块缓存，避免新增大幅序列帧。

最终完成条件：本轮 P0～P5 验收项闭合＋构建及全量门禁绿＋正式浏览器交互可用＋视觉样板与全地图检查证据齐。人工整季体验仍是整个游戏的独立交付条件，本视觉轮不以短样板代替整季验收。

## 7. 取舍、风险与需要重新决策的条件

| 问题 | 当前推荐 | 何时重新选择 |
|---|---|---|
| 改绘制还是换引擎 | 保留 Canvas、内联构建、现有图集；地面预烘进 chunk | 真实浏览器证据证明资源/缓存优化仍无法满足需求，才另立渲染技术评估 |
| 全量生图还是先做样板 | 先补少量高频素材；复用人物与家具 | 样板中比例、方向、夜景稳定后再批量生成 |
| 自建墙还是整栋建筑图 | 保持可拼接墙门＋独立家具 | 用户明确改变自由建房方向时重新讨论，不能仅为漂亮截图倒退 |
| 树木遮挡 | 保持稳定脚点、Y排序和清晰轮廓提示 | 实玩仍无法选人/操作时，再评估局部树冠处理；不改建筑透明规则 |
| 正式样板怎样产生 | 正式建造流程＋独立自动测试夹具 | 若希望新档直接赠送房间，涉及经济/教学变化，另行明确 |
| 迫降点体积 | 复用现有补给锚点，小型视觉组件 | 需要新增大型舱体碰撞、可拆资源或改变初始生成时先修订设计 |

仍待验证：白天和所有天气的最终色值、不同缩放下树冠遮挡、人物静态头像的裁切效果、旧式建筑与新家具的风格差、冷启动和图集内存成本。通过 P0/P2 实际画面决定具体数值，不在没有画面证据时写死最终调色。

安全并行仅适用于 P1 规格确定后的资产准备与独立测试设计；本轮不默认派实现子代理。`world.js`、`entities.js`、`ui.js`、`template.html`、CFG 和生成图集各保持单一修改负责人，避免多端同时接线。

开始实施只需用户明确指示执行本计划；按以上顺序推进。常规可逆实现不逐项重复索要许可；发现要改玩法、重要数据、存档契约或扩大范围时，先给出具体差异再确认。
