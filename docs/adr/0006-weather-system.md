# 家园天气系统：马尔可夫状态机 + 事件导演调度 + 暴露缝合

家园原本只有两条静态法则（酸雨/磁暴挂在星球法则里），居民暴露系统 `exposureTick` 有桩无驱动。决定：引入 RimWorld 式动态天气——12 种天气（晴/雨/大雨/雷暴/雪/暴雪/热浪/寒潮/酸雨/磁暴/雾/晴），马尔可夫概率级联切换（每种持续 1~5 天，极端天气带冷却），切换经 `APH.Events` 导演调度（ADR-12：所有随机压力单点收口，禁止模块私设计时器）。天气是家园场景的环境状态机，与远征环境法则（lw_*）完全独立。

**为什么马尔可夫链**：RimWorld 原教旨——天气是 storyteller 驱动的概率事件，不是固定轮换（太机械）也不是完全随机（一帧一切，无法策略应对）。纯函数 `tickWeather(state, dt, rng)` 注入随机源即可测。

**效果缝合（不新造机制）**：
- 居民侧：极端天气（雷暴/暴雪/热浪/寒潮/酸雨）→ `exposureTick` 激活（Survival #19 埋的桩终于接上）→ 不适心情 -4 → 急性伤病（现成链条）。
- 生产侧：农场 `farmMul` 乘天气项（雨+生长、酸雨减半、雪停滞）；磁暴窗口沿用 `harvestMods` 的 `lw_storm` 语义无缝接管。
- 玩家侧：室外减速（雨 30%/雪 20%/暴雪 40%）、HUD 天气行+预警。**显式裁剪：玩家不新增 exposure 条**——玩家已有饱食/精力/病情/血/氧五条，天气对玩家的惩罚收敛为「减速+环境提示」，与居民同规则但轻量（记录此裁剪，防后人补条）。
- 敌人侧：雾天感知半径 -30%（复用 nightAggroMul 乘法节奏）。

**为什么走导演而不是新计时器**：ADR-12 是铁律——所有随机压力（袭击/疫病/耀斑）统一经 `APH.Events` 的 directorTick 调度。天气是随机压力源，进事件卡组（`ev_weather`），喘息窗口/怜悯复用。天气模块只做「当前状态+效果表」纯函数，不持计时器。

**代码里没有天气渲染引擎**：雨/雪/雾粒子走程序化绘制（world.js 现有昼夜洞光粒子管线），不进水 sprite 管线（ADR-11 是对「序列帧」的约定，天气粒子是即时绘制，显式例外）。

**后果**：
1. 新模块 `src/weather.js`（`APH.Weather`），id 前缀 `wx_`（ADR-9 增补：`wx_clear/wx_rain/wx_rain_heavy/wx_thunder/wx_snow/wx_blizzard/wx_heat/wx_cold/wx_acid/wx_storm/wx_fog`；极光不做——`ev_aurora` 事件卡已是专属叙事，避免双轨）。
2. 存档：`meta.weather = { id, t }`，老档 `||默认 wx_clear`（零迁移）。
3. 效果表单点：`weatherEffects(id)` → `{speedMul, farmMul, exposureGain, enemySightMul, solarMul}`；**solarMul 为 T6 电网太阳能板预留**（晴天 1/雨 0.5/雷暴 0.15/暴雪 0.2/雾 0.6）——天气与建筑系统的联动接口，T6 接太阳能板时读它。
4. 测试：状态机（转移概率/持续时区/冷却）与效果表全纯函数 node 直测；场景冒烟验证渲染与接线。
