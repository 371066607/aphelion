# ADR-36: 美观 Beauty（P2 D2）

## 状态
已通过（Accepted） · 2026-09-07

## 上下文

`th_pretty_room`（「这屋子真漂亮」）在念头目录里躺了很久，**没有任何代码算过
「屋子好不好看」** —— `ctx.roomPretty` 从来没被谁设过。这是 P2 里唯一完全零实现的项。

已有的 `roomMoodGain` 是一个**只有正分**的原型：房间里有电视/书架/地毯就加分，
含居住舱再 +2。问题是**没有负分**，于是：

- 把木柴发电机、自动采矿机堆进卧室，**毫无代价**；
- 地上多脏、屋里摆着尸体，房间照样「好看」。

「布置房间」因此从来不是一个取舍 —— 只要往里塞家具就行。

## 决策

美观分 = **正分（复用 `roomMoodGain`：家具 + 卧室级）+ 工业负分 − 污秽 − 尸体**

```js
roomBeauty(pos, rooms, buildings, { filth, corpses })
  → { score, mood, pretty, ugly } | null   // null = 露天, 不谈美观
```

- 纯函数：污秽与尸体由调用方**按房间格子汇总**后传入，函数本身无副作用、node 直测。
- 工业负分进 `CFG.residents.beauty.ugly`（发电机 −3、采矿机 −3、工坊 −2…）——
  这才是真正的取舍：**别把发电机塞进卧室**。
- 尸体 −5/具，污秽 −0.6/单位。
- 结果汇入 ADR-31 的可变幅度念头：`th_pretty_room` / `th_room` / `th_room_bad`，
  **一个房间只挂一条**。

不做「按格子取平均」（环世界的做法）：本作房间尺寸差异不大，
总分模型更好解释，也避免大房间把家具稀释成 0。

## 两处被实测纠正的错误

两个都不会被单元测试抓到，都是跑了一遍真实模拟才看见的：

1. **`moodDiv` 悄悄砍半了既有平衡。** 最初设为 2，于是「卧室2+电视1+书架1=+4」
   变成 +2 —— 改动了本不该动的数值。改回 1:1。
2. **「装修更好反而心情更差」。** 跨进「漂亮」档时用了目录里的固定值 `+3`，
   而下一档的可变加成已经是 `+4`：多铺两块地毯，心情反而下降。
   现在「漂亮」档换文案但**沿用同一幅度**，并由测试锁住单调性。

实测（真实 `residentsTick` 出来的居民念头）：

```
空卧室            → th_room +2          目标 76
卧室+电视+书架     → th_room +4          目标 78
再加两块地毯       → th_pretty_room +6   目标 80
卧室里塞发电机     → th_room_bad -1      目标 73
卧室+矿机+发电机   → th_room_bad -4      目标 70
卧室里摆一具尸体   → th_room_bad -3      目标 61
```

## 后果

- `th_pretty_room` 终于有了真实来源。
- 污秽与尸体第一次有了**房间级**后果（此前只有各自的独立念头）。
- 清扫工作与埋葬工作的价值上升：它们现在也在保住房间美观。
- 「把工业区和居住区分开」成为一个真实的布局决策。
