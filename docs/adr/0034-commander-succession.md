# ADR-44: 指挥官倒下，有人接班

## 状态
已通过（Accepted） · 2026-09-07

---

## 上下文

BACKLOG 里挂了很久的一条：

> **指挥官死亡时控制权归谁**：现在指挥官一死就本局结束，但殖民地优先意味着
> 「还有人活着，殖民地就还在」。**这条会牵动整个操控范式，先别动手。**

先把现状数清楚。全项目「本局结束」有四个出口：

| 位置 | 触发 | 性质 |
|---|---|---|
| `combat.js hurtPlayer` | 远征战死 | 指挥官之死 |
| `main.js updateSurvival` | 远征缺氧 | 指挥官之死 |
| `main.js updateHome` | 家园击倒后无人救援，失血过多 | 指挥官之死 |
| `colonytick.js checkFall` | 立过殖民地再归零（T1） | 殖民地覆灭 |

**四分之三与设计支柱直接打架。** DESIGN 里「殖民地优先」是红线、
「不可动摇」，可实际规则说的是「指挥官即本局」。

（顺带澄清一处：家园其实已经**不会**直接死了 —— `hp<=0 && scene==='home'`
走的是击倒，只有无人救援倒计时归零才死。所以争议面比 BACKLOG 描述的更窄。）

---

## 决策

**指挥官倒下时，只要还有殖民者活着，就有人接过指挥权；本局继续。
本局结束的唯一出口，剩下殖民地覆灭。**

### 为什么不是「镜头脱离指挥官，转成纯上帝视角」

那是另一个自洽的答案（ADR-29 本来就是上帝视角），但它要付的代价太大：
`[E]` 交互 —— 睡觉、吃饭、招募、切菜谱、破译终端、登船 —— 全部挂在指挥官身上。
没有身体就没有这些动作，等于砍掉半个游戏。

### 为什么继任是对的

- 它是「殖民地优先」的直接推论，不是妥协。
- 所有现有系统一字不动地继续工作。
- **它把设计意图讲成了故事**：殖民地是主角，个人不是。
  你会失去跟了你三十天的那个人，然后另一个人走过来接手。

### 谁接班

**名册首位 = 加入顺序最早 = 最资深的那位。**
跟得最久的人接手，在这个故事里最自然，也不需要玩家再做一次选择
（他刚失去指挥官，不该在这时被弹一个下拉框）。

### 继任的代价必须是真的

- 名册 **−1**：接班的人从殖民者变成指挥官，殖民地少一个劳动力。
- 继任者**带着自己的身体状况上任**：他的饱食、精力、心情、病情原样保留。
  他刚经历了同一场灾难，不是满状态复活。（生命值是新的身体，所以回满。）
- 前任的技能没了。继任者用**自己**的技能 —— 谈判、破译从此按他的水平算。
- 死在远征：**背包与本次收益随人留在荒原**，镜头回家。
  「指挥官不再是本局」之后，这是远征风险仅剩的落点。
- 死在家园：**留下尸体**，让殖民地看得见代价。

## 实现

### 指挥官第一次有了身份

此前全项目写死 `{ id:'player', name:'指挥官' }` —— 因为他不可能被替换，
所以不需要身份。继任落地后他需要：

```js
meta.commander = { name, origin, skills, mainSkill, bio, succeeded }
```

`succeeded` 是第几任（0 = 初代）。老档缺失 → 补一位无名初代，**零迁移**。

初代**没有技能表**（`skills: null`），`Res.commanderSkill(meta, key, fallback)`
会回退到各调用点原先写死的值 —— 所以**初代的行为一字未变**，
只有继任者开始用自己的真实技能。

### 一个决策点，三处汇流

```js
APH.ColonyTick.commanderFell(reason, at)
  → Res.succeedCommander(meta)
      ok    → 交接、发 commanderSucceeded、本局继续
      !ok   → mode='dead'、发 death（stats.lastCommander）
```

`combat.js` 加载早于 `colonytick.js`，够不着它，所以发 `commanderFell` 事件。
**订阅点放在 `colonytick.js` 自己而不是 `main.js`** —— 不装 main 的测试入口
也得能走完死亡链路，否则那里的玩家会「死不掉」，而用例还是绿的。

### 界面

- 飘字：`⭐ 前任 倒下了 · 继任者 接过了指挥权`
- 复用发现卡讲清楚这一刻，卡头小字从「异常已录入数据库」换成
  **「指挥权交接」**（为此给卡片加了 `dcKind`，`showCard(name, lore, kind)`）
- 检查器与工作面板从写死的「⭐ 指挥官(你)」改成叫他的名字

## 护栏

`tests/succession.test.js` 8 条：有人接班则本局继续、名册空才结束且带
`lastCommander`、继任者带自己的状态上任、家园留尸体、远征丢背包且镜头回家、
身体挪到继任者站位、**覆灭判定仍是唯一失败出口**、老档零迁移。

ADR-40 把死亡结算改走总线之后，打桩公开方法已经拦不住了，用例其实在空转。
改成订 `death` 事件，测的是契约而不是内部调用。

## 后果

- 「本局结束」现在只有一个出口：**殖民地覆灭**。规则终于和设计支柱一致。
- 远征的风险从「可能直接输」变成「可能赔上一个人和一趟收益」——
  更符合 T4「远征是补给不是主线」的定位。
- 开了一条新的叙事线：一局游戏会有第二任、第三任指挥官。
  结算页的「存续天数」从此讲的是殖民地的故事，不是某个人的。
