# ADR-32: 家园每帧四段式（感知 / 模拟 / 提示 / UI 同步）

## 状态
已通过（Accepted） · 2026-09-07

## 上下文

`updateHome` 一个函数 311 行，把四件事搅在一起：

- 约 15 次逐帧邻近扫描（`s.nearPad` / `s.nearBed` / `s.nearKitchen` …）
- 模拟推进（自治、回血、击倒、居民、建造、生产、袭击）
- 十几处 `APH.UI.setHint(...)` 散落其间
- 底栏标签高亮与失效规划标记清理

提示语的优先级**没有任何一处写下来**——它是「后一次 `setHint` 覆盖前一次」
的副产物：谁在函数里写得靠后谁就赢。

对着实际行为跑一遍特征化（21 个场景）后发现，这直接造成了一个线上 bug：

```
near_kitchen  :: ⚡ 磁暴 · 实验室停摆      ← 本该是「[F] 切换菜谱」
near_workshop :: ⚡ 磁暴 · 实验室停摆      ← 本该是「[F] 切换配方」
near_bed      :: ⚡ 磁暴 · 实验室停摆      ← 本该是「[E] 上床睡觉」
near_cooler   :: ⚡ 磁暴 · 实验室停摆      ← 空调提示从来没有显示过
```

天气播报写在邻近提示**之后**，于是磁暴/酸雨期间，玩家站在任何建筑旁都看不到
该按什么键。空调提示更是被开场目标唠叨永久遮住，一次都没露过面。

## 决策

拆成四个函数，`updateHome` 只负责编排：

```js
function updateHome(dt){
  senseHome();                       // 只写 s.nearX，不做决策、不发提示
  var env = simHome(dt);             // 推进世界，返回提示层要用的环境量
  var hint = hintForHome(APH.state, env);
  if(hint != null) APH.UI.setHint(hint);
  syncHomeChrome();                  // 标签栏高亮 + 失效规划标记清理
}
```

`hintForHome` 是一张**显式优先级表**，命中即停；`null` = 这一档没意见，
交给下一档；`''` = 明确要求清空：

1. 物资告急
2. 指挥官自身状态（昏迷 / 饥饿 / 睡眠 / 困倦 / 作业）
3. 站在旁边能按键交互的东西 ← **交互提示从此不会被环境播报盖掉**
4. 远古遗迹（远征）
5. 环境播报（治疗中 / 天气）
6. 开场目标唠叨（垫底）

## 后果

- 改优先级改那张表，不再靠调整调用顺序。
- 上面四条提示 bug 一并修好；空调提示第一次真正可见。
- 特征化对拍：除这几条**有意修好的**之外，21 个场景其余输出与重构前逐字节相同。
- 优先级由 `tests/scenario.test.js` 的 `#ADR32 hint:` 系列锁死。

## 铁律

新增提示不要再写 `setHint`，写进 `hintForHome` 的表里，并想清楚它该排第几。
